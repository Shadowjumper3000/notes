# High-Performance Computing (HPC)

High-Performance Computing (HPC) leverages clusters of computers to solve complex computational problems faster than conventional systems, achieving the greatest computing capability possible at any point in time with available technology.

---

## Key Requirements of HPC

### Primary Requirement
The defining characteristic that differentiates HPC from other computing systems is:

- **Parallel Processing**: Coordinated operations across multiple processors to execute tasks simultaneously, enabling the solution of large-scale problems that a single processor cannot handle efficiently.

### Other Important Requirements
1. **Scalability**: The system's capability to grow in size and performance without disrupting existing workloads.
2. **High-Speed Interconnects**: Fast communication links between processors, memory, and storage to minimize bottlenecks.
3. **Reliable Storage**: Large, fast, and dependable data storage systems to support high data throughput and reduce I/O delays.
4. **Efficient Cooling**: Effective thermal management to counteract heat generated by intensive processing.
5. **Fault Tolerance**: The ability to handle hardware or software errors without significant data loss or computational downtime.

---

## Performance

- **Performance Metrics**: HPC performance is typically measured in *FLOPS* (Floating-Point Operations Per Second).  
- **Factors Influencing Performance**:
  - **Clock Rate**: The speed at which a processor executes instructions.
  - **Hardware Parallelism**: The number of simultaneous operations that the computer architecture supports.
- **Sustained Performance**: The actual real-world performance observed during typical workloads.  
- **Benchmarks**: Standardized tests (e.g., Linpack) used to compare different systems running the same applications.  
- **Degradation**: Performance reduction due to resource contention, communication overhead, or thermal throttling.  
- **Improvements**: Achieved through better parallel algorithms, faster interconnects, or optimized hardware.

### Peak Performance vs Sustained Performance
- **Peak Performance**: Maximum theoretical performance under ideal conditions.  
- **Sustained Performance**: Real-world performance considering communication delays, memory access latency, and workload imbalance.

## Partitioning in HPC Systems

High-performance computing (HPC) systems are designed to handle extremely large-scale computational tasks, often beyond what a single workstation can manage. To optimize performance, HPC resources are **partitioned** into specialized categories based on the type of workload they handle. This allows the system to allocate resources efficiently and ensures users run their jobs on the most appropriate hardware.

### 1. **CPU Partitions**

- **Definition**: CPUs (Central Processing Units) are general-purpose processors optimized for sequential and parallel workloads with complex branching and memory access patterns.

- **Characteristics**:
    - High clock speed for serial tasks.
    - Multiple cores (often tens to hundreds in HPC nodes) to handle parallel threads.
    - Large caches to reduce latency for memory-intensive operations.
    - Good for tasks with irregular computation patterns (e.g., simulations with dynamic branching or dependency-heavy algorithms).

- **Use Cases**:
	- Scientific simulations (fluid dynamics, structural analysis).
	- Data preprocessing or postprocessing pipelines.
	- Workloads that require high memory bandwidth or frequent branching.

### 2. **Accelerator / Booster Partitions**

- **Definition**: Boosters are specialized computing units designed to accelerate specific types of workloads, typically highly parallel or compute-bound tasks. Examples include GPUs, FPGAs, and AI accelerators.

- **Characteristics**:
    - Thousands of simple cores optimized for SIMD (Single Instruction, Multiple Data) or SIMT (Single Instruction, Multiple Threads) operations.
    - High floating-point throughput and memory bandwidth.
    - Often rely on host CPUs for orchestration and I/O management.

- **Use Cases**:
    - Matrix-heavy computations (linear algebra, deep learning, quantum simulations).
    - Rendering and visualization tasks.
    - Monte Carlo simulations, molecular dynamics, and other highly parallel workloads.


### 3. **Partitioning Logic**

- HPC schedulers (like Slurm, PBS, or LSF) manage access to partitions. Each partition can be tuned with:
    - Node type (CPU-only vs. GPU-accelerated).
    - Memory per node.
    - Number of cores or GPUs per job.
    - Specialized interconnects (InfiniBand vs Ethernet) for communication-heavy tasks.

- Users select a partition based on the **computational profile** of their workload. Suboptimal partition selection can lead to underutilization of resources or excessive wait times.


### 4. **Advanced Partitioning Considerations**

- **Hybrid Nodes**: Some partitions combine CPUs and GPUs, letting workloads exploit both sequential and massively parallel compute units.

- **Priority and QoS**: Partitions can enforce policies, reserving high-performance resources for time-critical workloads.

- **Topology-Aware Scheduling**: HPC systems often partition based on network locality to reduce communication latency for tightly coupled parallel applications.

---

## Scaling

- **Strong Scaling**: Increasing the number of processors while keeping the problem size fixed, aiming to reduce execution time.  
- **Weak Scaling**: Increasing both the problem size and the number of processors proportionally to maintain constant execution time.  
- Efficient scaling requires minimizing communication overhead and balancing workload across all processing units.
